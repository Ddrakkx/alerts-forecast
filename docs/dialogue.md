## Твої два питання

**1. Тривоги, які ще не закінчились**

README про це пише лише для волонтерського набору. Якщо повідомлення про кінець не було, рядок позначають `naive=True`, а `finished_at = started_at + 30 хв`. - Для цілі «почнеться тривога в (t, t+H]» ми використовуємо лише `started_at`, тому вигаданий кінець її не псує.

## 3. Крок 2 без коду: цільова і сітка

**Час.** Усе в UTC, київський час лише для календарних ознак (година доби, день тижня).

**Сітка.** Моменти прогнозу `t` кожні 15 хв по UTC (:00, :15, :30, :45). «Прогноз у `t`» означає, що ми знаємо все, що сталося до `t` включно.

**Що відомо в `t`.**
- Тривога з `started_at ≤ t` відома.
- Тривога вважається активною, якщо `started_at ≤ t < finished_at`. Ми використовуємо лише факт «ще не закінчилась», але не значення `finished_at`. Ознаки типу «скільки лишилось» заборонені.
- Тривоги з `started_at > t` для ознак не існують.

**Ціль.** `y_H(t) = 1`, якщо існує тривога зі стартом у півінтервалі `(t, t+H]`, для `H ∈ {1, 3, 6}` годин. Старт рівно в `t` — вже минуле, тому інтервал відкритий зліва.

**Основна вибірка.** Лише ті `t`, де тривоги в момент `t` немає. У волонтерських даних тривоги по області не перекриваються, тож для активних `t` ціль означала б «перезапуск після кінця поточної», а це інше питання. Їх залишаємо для додаткової оцінки.

**Межі.** Мітку на моменті `t` можна рахувати лише якщо `t+H` не виходить за кінець даних. Кінцем даних беру час знімка (коміт датасету 09.10.2026 05:17 UTC), хоча в самих даних остання тривога раніше. Тому останні `H` годин відкидаємо.

**Контракт від витоку, який перевіряє тест.** Для випадкових `t` обрізаємо дані на момент `t` (прибираємо тривоги зі стартом після `t`, а в активної тривоги ховаємо `finished_at`) і перераховуємо ознаки. Результат має збігтися з тим, що дає повний набір.
